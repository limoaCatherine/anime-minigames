## 1. 工程说明（给开发同事）

```
微信小游戏/
├─ game.js                 主包代码 (esbuild 打包，wx 平台层)
├─ game.json               竖屏、隐藏状态栏、subpackages 分包配置
├─ project.config.json     compileType: game；appid 目前是 touristappid (占位)
├─ assets/                 主包资源：头像 / Boss / 菜单背景 / 预渲染音效 wav / 转发卡片图
├─ sub_art/   (分包 art)   半身立绘
├─ sub_bgm/   (分包 bgm)   背景音乐 mp3 (循环 + 1 秒 overrun 版)
├─ sub_voice/ (分包 voice) 角色语音 mp3
├─ README_微信工程.txt     (packOptions.ignore，不进代码包)
└─ 上架资料/               本说明、商店文案、隐私自查草案、5 张截图 (packOptions.ignore，不进代码包)
```

- **AppID 和激励视频广告位 ID 只在 `src/config/PlatformConfig.js` 的 `wechat` 字段填写**，填好执行 `npm run build:wechat` 重新生成工程（会写进 project.config.json 和 game.js）。不要手改 `微信小游戏/` 里的文件。
- 包体（官方限制：「整个小游戏所有主包+分包大小不超过 30M；主包不超过 4M；单个普通分包不限制大小；单个独立分包不超过 4M」）：
  - 主包约 1.62 MB / 4 MB；分包 art 0.83 MB、bgm 2.30 MB、voice 3.07 MB；合计约 7.8 MB / 30 MB。构建时自动检查，超限会报错退出。
  - 代码包只含官方上传白名单内的后缀（js / json / png / jpg / mp3 / wav），构建时检查。
- 已接入的 wx 接口：`createCanvas`（首个为上屏画布）、`createImage`、`getWindowInfo`（安全区，旧基础库退回 `getSystemInfoSync`）、`getMenuButtonBoundingClientRect`（避开右上角胶囊）、`onTouchStart/Move/End/Cancel`、`getStorageSync/setStorageSync`、`createInnerAudioContext`（mp3；BGM 两个实例在循环点等功率交叉淡化，无缝循环）、`onShow/onHide`（切后台自动暂停、停音乐）、`loadSubpackage`（进菜单后后台依次下载立绘 → 音乐 → 语音，失败自动重试一次，没下完也能开玩）、`createRewardedVideoAd`、`showShareMenu`（发送给朋友 + 分享到朋友圈）、`onShareAppMessage`、`onShareTimeline`、`shareAppMessage`（结算页「分享给好友」）、`showToast`、`vibrateShort`、`getLaunchOptionsSync`。
- 已去掉的抖音专有能力：游戏录屏 / 录屏分享、侧边栏复访（微信包里不含相关代码和文案，构建时替换为空实现）。
- **广告位 ID 为空（当前状态）**：所有「看广告」按钮（换一批 / 结算翻倍）隐藏，复活改为每局免费一次「再试一次」，不创建任何广告实例。填上 ID 重新构建后自动恢复激励视频（复活 / 换一批 / 翻倍），看完（`onClose` 的 `isEnded=true`）才发奖励，中途关闭或拉取失败不发奖励、不扣次数。
- 朋友圈分享：官方说明 `wx.onShareTimeline`「本接口为 Beta 版本，暂只在 Android 平台支持」，iOS 用户右上角只有「发送给朋友」，属正常现象。
- 测试：`npm run test:wechat`（构建 + 在 Node 里用 wx 模拟跑真正的 game.js 冒烟测试）。

## 2. 注册小游戏并完成主体认证，拿到 AppID

官方：「微信小游戏是小程序的一个类目。用户完成小程序注册后，可选择"游戏"类目并开始开发、调试小游戏」。

1. 打开 https://mp.weixin.qq.com → 立即注册 → **小程序**。填一个**未被其他公众号 / 小程序用过的邮箱**，激活邮件。
2. 主体类型选**企业**，填写 **上海盖姆艾尔网络科技有限公司** 的营业执照信息、管理员身份信息。**【📱扫码】** 管理员用自己的微信扫码完成身份绑定。
3. 进入后台后在「设置」里设置**服务类目 = 游戏**（选最贴近的子类目，例如休闲 / 动作）。⚠️ 官方审核规范 2.1.3：「一旦你选择了游戏类目，该类目将不可修改变更为其他小程序类目」。
4. **微信认证**（设置 → 微信认证）：企业主体按页面提交材料、完成对公打款或法人验证；认证审核费用以页面为准。**【📱扫码】** 管理员扫码确认。官方：「企业主体必须进行微信认证才能提交小程序备案」。
5. AppID：MP 后台 → 开发 → 开发管理 → 开发设置 →「AppID(小程序ID)」，形如 `wx0123456789abcdef`。
6. 把 AppID 发给开发同事填进 `src/config/PlatformConfig.js` → `wechat.appid`，执行 `npm run build:wechat`。（也可以在开发者工具导入时直接填，见第 6 节。）
7. 「开发者」权限：如果上传代码的人不是管理员，管理员在 MP → 管理 → 成员管理 里把他加为开发者（对方需 **【📱扫码】** 确认）。

## 4. 资质审核与「版号」——核实结论

**结论：本游戏无内购、无虚拟支付、只靠广告变现（IAA），按微信官方流程走「情况二」，不需要提交《网络游戏出版物号核发单》（版号）；需要的是「资质审核（IAA）」+「小游戏备案（前置审批）」+「小程序备案（工信）」。**

官方依据（原文摘录）：
- 《小游戏接入指南》：「审核时效：（1）不开通虚拟支付游戏：IAA游戏发布指引，预计需 13 - 37 个工作日；（2）开通虚拟支付游戏：IAP游戏发布指引，预计需 9 - 22 个工作日」。
- 《IAA 游戏发布指引》：「IAA 游戏指的是通过广告来实现盈利的游戏」。
- 《资质审核(IAA)》：「IAA 游戏选择情况二：小游戏当前及未来均不需要开通虚拟支付」；「选择与游戏内容一致的游戏三级类目」「选择不申请支付资质」；材料要求：「IAA 游戏进行备案时，遇以下情形需要提交《计算机软件著作权登记证书》或对应其他授权材料：1）游戏名称含有英文、或"软件"字样；2）涉及相关品牌、公众人物合作等」。
- 对照《资质审核(IAP)》：IAP 才要求「材料 1 - 网络游戏出版物号核发单（必填）」「材料 2 - 计算机软件著作权登记证书（必填）」。
- 《小游戏备案》Q8：「如确认当前游戏并未获得对应版号……点击「上一步」返回，选择"情况二：小游戏当前及未来均不需要开通虚拟支付"，按指引前往小程序备案完成后续步骤即可。」Q5：「已提供《网络游戏出版物号核发单》或版号批复文件的游戏暂无需提交小游戏备案」——即没有版号的 IAA 游戏用「小游戏备案」（由平台初审后递交主管部门审批）代替。

由此推出的要点（请你知悉）：
1. **软著**：游戏名「星屑轮舞」为纯中文、不含「软件」字样、不涉及品牌 / 公众人物合作 → 按上面原文**不在必须提交软著的情形内**。但平台审核时仍可能要求补充材料；如果你想稳妥，可以以「上海盖姆艾尔网络科技有限公司」为著作权人申请软著（软件名称与小游戏名称一致）。语音素材为 VOICEVOX 各角色（按其利用规约商用 + 署名），不属于「品牌、公众人物合作」，但如审核员要求授权说明，可提供 `docs/licenses/` 下的规约记录。
2. **「当前及未来均不需要开通虚拟支付」是一项承诺**。以后如果想加内购，就要按 IAP 补齐版号和软著，届时要重新走资质 / 备案。
3. 未核实 / 无法替你判断的点：官方文档写的是流程分支与材料清单，**没有一句话写成"无内购游戏不需要版号"这样的法律结论**；国家主管部门对"未取得版号的网络游戏"的监管口径在网页文档里也没有展开。上面的结论是"按微信平台现行流程，IAA 游戏不要求提交版号"；如需法律层面的确认，请咨询主管部门或法务。官方社区（非正式文档）也有工作人员答复"游戏无内购、付费是不需要版号的"，仅供参考。

**操作**：MP 首页 → 小程序备案 → 小游戏备案&发布流程指引 → 资质提交（或 MP → 设置 → 游戏设置 → 资质管理 → 前往管理）→ 选「情况二」→ 选游戏三级类目、不申请支付资质 → 上传材料（如无需软著，按页面提示填写即可）→ 提交。办结时限官方写「正常情况：1-3 个自然日」。常见驳回：名称 / 主体不一致、公章模糊或用错章、签名或日期不完整——**材料上的主体一律写「上海盖姆艾尔网络科技有限公司」并加盖公章**。

## 5. 小游戏备案 → 小程序备案（工信）

1. **小游戏备案**（IAA 前置审批）：MP →「账号设置 → 小程序备案 → 去完善」→ 小游戏备案「前往提交」。要求「清晰、完整、真实介绍你所备案的小游戏内容，包括但不限于场景、玩法、功能等信息；并上传对应截图，截图需保持尺寸、版本一致」——玩法文字见 `商店文案.md`「玩法要点」，截图用 `上架资料/截图/` 这 5 张（同为 1080×1920、同为 v1.3.0）。时效：平台初审 1-2 个工作日，主管部门 10-20 个工作日。**提交后不要改名、不要迁移主体**。
2. **小程序备案（工信）**：前置审批通过后进入。流程「备案信息填写、平台初审、工信部短信核验、通管局审核和备案成功」。**工信部短信核验需要负责人在手机上按短信完成**（📱）。
3. 版本审核可以与小程序备案并行提交。

2. MP → 管理 → 版本管理 → 开发版本「提交审核」。按提示完善**游戏内容介绍**（简介、玩法、截图——用 `商店文案.md` 与 5 张截图）。
3. 必填：**游戏自审自查报告**、**版本更新说明**（官方发布流程原文：「其中：[游戏自审自查报告]和[版本更新说明]是必填的，其他为选填」）。
   - 自审自查报告：官方没有固定模板；内容写明游戏名称、主体、版本、玩法概述，逐条声明「无违法违规内容、无色情暴力血腥、无赌博 / 抽奖、无内购及虚拟支付、无诱导分享、无陌生人社交、已设置适龄提示」等，**落款「上海盖姆艾尔网络科技有限公司」并加盖公章、写明日期**，拍照或扫描上传。
   - 版本更新说明：见 `商店文案.md` 末尾。
4. 游戏引擎一栏：本游戏为原生 Canvas 2D + JavaScript（无第三方引擎），按页面选项填写「其他 / 自研」。
5. 审核规范里与本游戏相关、需要你确认的点：
   - 3.2.8.9「不能包含赌博、有奖竞猜和抽奖的内容」：本游戏升级三选一与宝箱为纯游戏内随机，不涉及付费，不属于付费抽奖。
   - 3.6.6「如相关法律法规规定提供服务的界面必须进行特别信息标识的，应予以明确标识。如小游戏必须在游戏开始画面显著位置标明游戏的批准文号、网络游戏出版号以及著作权登记号，全文登载《健康游戏忠告》等。」——本游戏无版号；健康游戏忠告由平台启动页展示（见第 3 节）。若审核要求游戏内也展示，可在标题页加一屏《健康游戏忠告》后重新提审。
   - 不要诱导分享（如"分享才能复活"）：本游戏分享不给任何奖励，符合要求。

## 8. 发布

审核通过后会在「微信 → 服务通知」收到提醒。前提是**版本审核和备案都已完成**（官方：「小游戏发布前，必须先完成版本审核和备案流程」）。MP → 版本管理 → 审核版本 →「提交发布」→ 全量发布。

## 9. 流量主与激励视频广告位

1. **开通条件**（官方《广告》，满足任一即可）：
   - 条件一：「小程序累计独立访客 (UV) > 500」且「无刷粉行为且未曾有严重违规记录」；
   - 条件二：「开通内置游戏圈并产生有效活跃」且「发布官方帖 5 篇」；
   - 条件三：同公司主体名下已有小程序已开通流量主、持续 1 个季度有变现且无违规，可直接开通。
   - 「流量主资格需要次日刷新，请于满足条件后次日再试」。
   → 也就是说**首个版本会在没有广告的状态下上线**（游戏已按此处理：广告按钮隐藏、复活免费一次）。
2. **开通**：MP 后台「功能 → 流量主」开通，按页面补充财务资料（结算账户须为公司主体）。
3. **新建广告位**：流量主 → 广告管理 → 新建「激励式视频」广告位（名称如「复活 / 刷新 / 翻倍」，一个即可，三处共用），得到广告单元 ID（形如 `adunit-xxxxxxxxxxxxxxxx`）。
4. **填 ID**：发给开发同事填进 `src/config/PlatformConfig.js` → `wechat.rewardedAdUnitId`，执行 `npm run build:wechat`（会自动恢复复活 / 换一批 / 翻倍三个激励视频入口），然后重新上传 → 提审 → 发布。
5. 新版本里激励视频只在玩家主动点击「看广告…」时播放，看完才发奖励；不会自动弹广告。
